# Vending Circuit Map

A self-contained, static web map of food-truck-vendable events for The Glizzness, reading
live from Supabase. Two-tier, rendering-minimal: **market hubs → click a hub → its events →
click an event → detail drawer** (with the event's homepage link shown only when one exists).

No build step, no server, no framework. Plain HTML + Leaflet + vanilla JS.

## Files
| File | Purpose |
|---|---|
| `index.html` | Markup, styling, Leaflet + script includes |
| `app.js` | Map logic: load markets/events from Supabase, two-tier render, detail drawer |
| `config.js` | Supabase URL + **anon public** key (you fill the key) |

## Setup (one step)
1. Supabase dashboard → **Project Settings → API** → copy the **`anon` `public`** key.
2. Paste it into `config.js` as `SUPABASE_ANON_KEY`.

The anon key is **safe to expose** in a client app: the `vending_*` tables have public-read
RLS policies; the accounting tables have **no** policies and stay blocked. The map can only
read the vending data.

## Run locally
Just open `index.html` in a browser (double-click), or serve the folder:
```
python -m http.server 8000        # then visit http://localhost:8000/vending-map/
```

## Deploy (free options)
- **GitHub Pages:** enable Pages on the repo → the map is at `…/vending-map/`.
- **Netlify / Cloudflare Pages:** drag-drop the `vending-map/` folder, or connect the repo.

(For GitHub Pages the committed `config.js` must contain the real anon key — that's fine, it's
public-safe.)

## Publish on glizzness.com — branded subdomain (chosen approach)

Decision (2026-06-17): host this folder on a free static host and serve it at
**`festivals.glizzness.com`**, linked from the glizzness.com menu. Chosen over pasting
`embed.html` because the map reads live from Supabase and we iterate on it — push-to-deploy
beats re-pasting a file on every change, and we get full height + a clean URL.

**Steps:**
1. **Host the folder.** Cloudflare Pages or Netlify — connect the GitHub repo (`lazrexmc/glizzness`)
   and set the project root/publish directory to `vending-map/`. Every `git push` to `master`
   auto-deploys. (Or drag-drop the `vending-map/` folder for a one-off deploy.)
2. **Point the subdomain.** In **GoDaddy → DNS** add a `CNAME` record:
   `festivals` → your host's target (e.g. `your-site.pages.dev` or `your-site.netlify.app`).
   Add `festivals.glizzness.com` as a custom domain in the host's dashboard; it auto-issues the
   HTTPS cert.
3. **Link it.** In the GoDaddy site menu add a link to `https://festivals.glizzness.com`.

The committed `config.js` already holds the real anon key — public-safe (vending_* tables are
read-only via RLS; accounting tables have no policy and stay blocked).

### Fallbacks (only if a subdomain isn't wanted)
`embed.html` is a single self-contained file (Leaflet via CDN; `config.js` + `app.js` inlined),
regenerated by `python build_embed.py` whenever `index.html`/`app.js`/`config.js` change.
- **In-page iframe:** host the folder, paste into a GoDaddy Custom Code block:
  ```html
  <iframe src="https://festivals.glizzness.com" style="width:100%;height:85vh;border:0" title="Vending Circuit"></iframe>
  ```
- **Paste embed.html:** add a GoDaddy Custom Code / HTML section and paste all of `embed.html`.
  GoDaddy sandboxes it in an iframe (scripts run); give the section a tall height. Re-paste on
  every change — least convenient.

## Data source
Reads three REST endpoints with the anon key:
- `vending_markets` — 17 hub pins (Tier 1)
- `vending_events` (`lat not null`) — all 127 events; the publish gate
  (`verification_status in (verified,partial)`, `food_truck_friendly <> excluded`) is applied
  **client-side** so the defunct/excluded toggle can reveal the other 3 on demand
- `vending_event_schedules` (`event_id, month`) — powers the month filter

All fetched once on load (small payload); rendering is tiered so only one market's pins are on
the map at a time. To change what's published, edit the rows in Supabase (or re-run the ETL +
reload) — the map reflects it on refresh.

## Architecture notes
- **Tier 1** renders only the 17 market circle-markers (sized by event count).
- **Tier 2** clears the hub layer and renders just the selected market's event markers
  (colored by food-truck-friendliness), fit-bounds to them.
- **Tier 3** opens the side drawer with dates, size, distance/trip-type, application method,
  contact, fee (if known), notes, and a conditional **Event page** button.
- "← All markets" returns to Tier 1.

## Phase 6 (built)
- **Filters** (filter bar): by month, food-truck-friendliness, and trip-type. Month uses
  `vending_event_schedules.month`; year-round/recurring events (no month) match any month.
  Filtering recomputes Tier 1 market counts and Tier 2 event pins; markets with zero matches dim.
- **Defunct/excluded toggle:** all events are fetched; defunct + excluded are hidden by default and
  shown (styled red, with a status badge in the drawer) when toggled on.
- **Mobile polish:** full-width drawer, wrapping filter bar, condensed legend on small screens.

Marker clustering was intentionally **not** built — the two-tier render shows one market's pins at a
time (almost always <20), so clustering adds a dependency for no benefit.
